# Функциональные требования MVP

## 1. Назначение

CLI Task Manager — консольное приложение для управления личными задачами.

Пользователь взаимодействует с приложением через интерактивное меню в терминале. В MVP доступен только CLI-интерфейс. В дальнейшем приложение может быть расширено другим интерфейсом, например веб-интерфейсом.

## 2. Модель задачи

Каждая задача содержит следующие поля:

| Поле | Описание | Обязательность |
| --- | --- | --- |
| `id` | Уникальный идентификатор задачи | Да, создаётся автоматически |
| `title` | Название задачи | Да |
| `priority` | Приоритет задачи | Нет |
| `deadline` | Дедлайн задачи | Нет |
| `status` | Текущий статус задачи | Да |
| `created_at` | Дата и время создания задачи | Да, создаётся автоматически |

### 2.1. Приоритет

Приоритет может принимать целое значение от `1` до `5`:

- `1` — самый низкий приоритет;
- `5` — самый высокий приоритет.

Приоритет является необязательным полем.

### 2.2. Статус

Допустимые статусы задачи:

- `todo`;
- `in_progress`;
- `done`.

Новой задаче автоматически присваивается статус `todo`.

### 2.3. Дедлайн и просроченность

Дедлайн является необязательным полем. Пользователь может создать задачу без дедлайна. Если дедлайн указывается, он вводится в формате `YYYY-MM-DD`.

При создании задачи дедлайн не может быть раньше текущей даты или совпадать с ней. Минимально допустимый дедлайн — следующий календарный день.

Если текущая дата позже даты дедлайна, а статус задачи не равен `done`, задача считается просроченной. В день дедлайна задача не считается просроченной. Просроченность не является отдельным статусом и определяется автоматически на основе дедлайна, текущей даты и статуса задачи.

Просроченные задачи автоматически не удаляются.

## 3. Главное меню

Главное меню должно предоставлять следующие действия:

1. Создать задачу.
2. Посмотреть задачи.
3. Изменить статус задачи.
4. Удалить задачу.
5. Фильтровать задачи.
6. Сортировать задачи.
7. Выйти из программы.

## 4. Создание задачи

При создании задачи:

- пользователь указывает обязательное название (`title`);
- пользователь может указать приоритет (`priority`);
- пользователь может указать дедлайн (`deadline`);
- статус автоматически устанавливается в `todo`;
- идентификатор (`id`) создаётся автоматически;
- дата и время создания (`created_at`) создаются автоматически.

Пустое название задачи не допускается. Некорректный приоритет и дедлайн, не соответствующий формату `YYYY-MM-DD`, должны обрабатываться программой.

## 5. Просмотр задач

Пользователь должен иметь возможность посмотреть список всех задач.

Для каждой задачи отображаются как минимум:

- `id`;
- `title`;
- `status`;
- `priority`;
- `deadline`.

Если задача просрочена, это должно быть явно обозначено для пользователя.

## 6. Изменение статуса

При изменении статуса:

1. Пользователю показывается список задач.
2. Пользователь выбирает задачу по `id`.
3. Пользователь выбирает новый статус: `todo`, `in_progress` или `done`.

Если задача с указанным `id` не существует, программа должна корректно сообщить об этом.

## 7. Удаление задачи

Пользователь выбирает задачу по `id`. Перед удалением программа должна запросить подтверждение.

Если задача с указанным `id` не существует, программа должна корректно обработать ситуацию.

## 8. Фильтрация задач

В MVP должна поддерживаться фильтрация задач:

- по статусу;
- по приоритету;
- только просроченные задачи;
- только задачи с дедлайном;
- только задачи без дедлайна.

Пользователь может одновременно применять несколько фильтров. В этом случае в результат попадают только задачи, удовлетворяющие всем выбранным условиям.

## 9. Сортировка задач

В MVP должна поддерживаться сортировка задач:

- по приоритету;
- по дедлайну;
- по дате создания.

Пользователь должен иметь возможность выбрать порядок сортировки:

- по возрастанию;
- по убыванию.

После сортировки задачи отображаются пользователю в выбранном порядке. При сортировке по необязательному полю задачи без значения этого поля отображаются после задач, у которых значение задано, независимо от выбранного направления сортировки. Сортировка одновременно по нескольким полям в MVP не входит.

## 10. Выход из программы

При выборе выхода программа должна запросить подтверждение.

- Если пользователь подтверждает выход, программа завершается.
- Если пользователь отменяет выход, программа возвращается в главное меню.

## 11. Обработка ошибочных ситуаций

Программа должна корректно обрабатывать как минимум следующие ситуации:

- пустой `title`;
- приоритет вне диапазона `1–5`;
- некорректный формат дедлайна;
- несуществующий `id`;
- некорректный пункт меню;
- некорректный статус.

Обычные ошибки пользовательского ввода не должны приводить к аварийному завершению программы.

## 12. Не входит в MVP

В MVP не реализуются:

- регистрация;
- авторизация;
- несколько пользователей;
- подзадачи;
- критерии приёмки задачи;
- категории;
- теги;
- веб-интерфейс;
- автоматическое удаление просроченных задач;
- сортировка по нескольким полям.
